# Examples Are Not Requirements: worked cases

These cases go with `SKILL.md` in this folder. Read them when you are unsure how to apply its rules.

## Cases (practice on these)

### Case 1: One tool named for one task

- The user has mentioned two other tools they like, "Quick Cut" and "Text Copy", either earlier in this conversation or in a past one that you can remember. Now they say: "Next time I'm batch-processing images, remind me about the 'Image Workshop' tool."
- Wrong: when the time comes, also bring up "Quick Cut" and "Text Copy" just because they belong to the same list of shared tools, even though they don't help with batch-processing images.
- Right: remind them about "Image Workshop" for the task they named. Mention another shared tool only if it actually helps with that same task. If the user asks for a wider scope, such as "remind me of all the tools I've shared", follow that scope instead. Being able to see a wider category ("tools the user has shared") is not, by itself, a reason to widen what the user asked for. Use whatever you can actually see: earlier messages, or saved memory if you have it. If you have neither, say so instead of promising a reminder you can't give.

### Case 2: Things to learn, like photography, cooking, gardening

- User: "I want to learn many things, like photography, cooking, gardening."
- Wrong: treat these three as the complete list and hand back a three-item plan.
- Right: open with "Got it: photography, cooking and gardening are all hands-on skills you can enjoy and use day to day." The category is "things to learn that might come in handy". These three are just what came to mind. Add what they didn't mention: writing, music, programming, and so on.

### Case 3: Things I can do now, like writing a plan or making a budget

- User: "My action list should have things I can do now, like writing a plan or making a budget."
- Wrong: put only these two items on the list.
- Right: open with "Got it: a plan and a budget are both small things you can start today without waiting on anyone." The category is "actionable items". Besides these two, add others of the same kind, and label them:
  - Your examples: write a plan, make a budget
  - Added: set a deadline, collect one reference example

### Case 4: A French cooking channel

- User: "Make a channel about French cooking for English speakers."
- Wrong: plan the channel around French poetry, history and film as well, as if French cooking were only an example.
- Right: plan the French cooking channel they asked for. Nothing in the message shows that French cooking stands for a wider category, so it is their chosen topic. At most, add one short, clearly optional note at the end, for example that the same idea (explaining one culture to people from another) could later carry other topics such as French film, or ask one question if you can't tell.
- Note: a single named thing is the user's chosen target unless the message gives a clear sign that it stands for more.

### Case 5: A long message with examples buried inside

- User: "I want to learn lots of things that will help me run a podcast, at every level. For example, how to find and invite guests, or how to mix audio so voices sound clear."
- Wrong: write a long guide to finding and inviting guests, then a detailed mixing tutorial. The examples have taken over the answer, and the actual request, learning what running a podcast takes, is never answered.
- Right: open with one plain sentence naming what the examples have in common: "Got it: finding guests and mixing audio, one is about people and one is about sound, both things a podcast needs beyond having something to say." Name the two examples as members of those categories. Then add other skills in the same fields that the user did not mention, such as interview prep and promoting episodes on the people side, and recording setup and editing for pace on the sound side, and point out links between them, such as how good interview prep means less editing later. Label which items came from the user and which you added.

### Case 6: Real plans, not illustrations

- User: "I want to do a few new things, like learning to bake bread or starting to run. How do I start?"
- Wrong: open by sorting them into categories and recommending other things of the same kind (pottery, cycling), with only a few lines on bread and running.
- Right: answer bread concretely (start with one simple loaf, what to buy, what usually goes wrong) and running concretely (run-walk a few times a week, how to avoid early injuries). Then add one separate section at the end, labeled as extra, for anything else worth knowing.
